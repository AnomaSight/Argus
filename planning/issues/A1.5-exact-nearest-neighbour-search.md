## Summary
Find the nearest memory-bank patch (and its distance) for every query patch, fast.

## Why this matters
Scoring, greedy sampling and reweighting all need nearest-neighbour distances. Exact search keeps results comparable to the papers.

## What to do
1. `memory/search.py`: `knn(queries, bank, k=1) -> (distances, indices)` using chunked `torch.cdist` on GPU so memory stays bounded.
2. CPU fallback with the same API (chunked NumPy/torch).
3. Choose chunk sizes from available memory; expose them as config.

## Deliverables
- `knn()` with GPU and CPU paths
