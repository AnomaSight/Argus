# [A2.3] Memory bank save/load with all four settings from one run

## Summary
Store the support features plus the greedy order, and materialise 100% / 10% / 1% / ASO banks by slicing.

## Why this matters
Avoids running greedy sampling more than once per seed, and gives `load_detector` a single on-disk format.

## What to do
1. `memory/bank.py`: `build_banks(support_features, seed) -> {m100, m10, m1, aso}`; m100 = all features, others = features[order[:k]].
2. Save per C3 location: features (float16), order, k per setting, preprocessing preset, backbone config hash.
3. Record bank size in MB and setup time (feature + greedy) for `run.json`.

## Deliverables
- Bank builder and on-disk format

## Done when
- [ ] One greedy run produces all four banks
- [ ] Reload gives identical arrays
- [ ] m1 is exactly the first 10% of m10's selection order
- [ ] Tests for this module pass in CI / `make test`
