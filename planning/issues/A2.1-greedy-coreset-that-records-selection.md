## Summary
PatchCore's greedy (farthest-point) coreset, run once to 10%, saving the order patches were picked and the representative distance at each step.

## Why this matters
Because greedy picks one patch at a time, the 1% and ASO coresets are prefixes of the 10% run. One run gives three memory settings, and d(k) is exactly the curve ASO needs.

## What to do
1. `memory/greedy_coreset.py`: random linear projection to 128 dims (Johnson–Lindenstrauss, as in the paper) for selection only.
2. Start from a seeded random point; keep a running min-distance vector; each step pick the argmax, record its index and d(k) = that max distance, update min-distances. All on GPU.
3. Return `order` (indices, length k₁₀%) and `d` (float array).

## Deliverables
- `greedy_coreset()` returning order and d(k)
